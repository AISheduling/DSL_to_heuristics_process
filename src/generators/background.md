# Фоновые сети

Модуль: `background.py`, функция `background_network(n, n_res, seed, ...)`.

## Идея

Мы строим обычный случайный проект, похожий на проекты PSPLIB, но без всяких ловушек. Он нужен
дважды. Во-первых, как фон, в который встраиваются ловушки (`traps/`): так ловушка оказывается
в проектах разного размера и структуры, а не в одном игрушечном примере. Во-вторых, как
контрольная группа: если правило проигрывает и на таком проекте, дело не в ловушке.

## Маленький пример

Схема сети из 6 работ в 3 слоях (`layers=3`):

```
слой 1      слой 2      слой 3
  a ───────▶ c ───────▶ e
  b ───────▶ d ───────▶ f
  a ───────────────────▶ f     (длинная дуга через слой)
```

- У каждой работы, кроме первого слоя, ровно одна короткая дуга из предыдущего слоя.
  Поэтому глубина сети равна числу слоёв.
- Остальные дуги длинные, через слой и больше; их в среднем `extra_preds` на работу.
  Так устроен PSPLIB: там почти нет «лишних» коротких дуг (индикатор LA ≈ 0).
- Транзитивные дуги удаляются: если есть путь a → c → e, дуга a → e не добавляется.
- Исток связан с работами без предшественников, работы без преемников — со стоком.

Ресурсы: каждая работа в среднем использует долю RF из n_res ресурсов, спрос от 1 до 10.
Ёмкость считается по определению силы ресурса RS (Kolisch):
`R_k = r_min + RS · (r_peak − r_min)`, где r_min — наибольший спрос одной работы, r_peak — пик
спроса, если все работы начать как можно раньше без учёта ресурсов. При RS = 0 ресурса хватает
ровно на самую «жадную» работу, при RS = 1 — на всё раннее расписание сразу.

## Параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `n`, `n_res` | — | число реальных работ и ресурсов |
| `seed` | — | один seed — один и тот же проект |
| `layers` | ≈ √(2n) | глубина сети: 8 слоёв при n = 30, 15 при n = 120 |
| `extra_preds` | 1.2 | среднее число длинных дуг в работу |
| `durations` | (1, 10) | диапазон длительностей |
| `rf`, `rs` | 0.5, 0.3 | RF и RS проекта |
| `max_demand` | 10 | наибольший спрос работы на ресурс |

## Насколько похоже на PSPLIB

20 seed на каждое n, параметры по умолчанию; PSPLIB — каждый восьмой инстанс набора:

| | CNC | OS | TF | LA |
|---|---|---|---|---|
| PSPLIB J30 | 1.40–2.07 | 0.27–0.60 | 0.09–0.41 | 0.00–0.19 |
| фон, n = 30 | 1.20–1.60 | 0.35–0.48 | 0.12–0.42 | 0 |
| PSPLIB J120 | 1.48–2.09 | 0.16–0.41 | 0.12–0.44 | 0.00–0.02 |
| фон, n = 120 | 1.55–1.76 | 0.31–0.38 | 0.16–0.28 | 0 |

RS достигается с точностью 0.5 / (r_peak − r_min), потому что ёмкость целая.

## Сокращения

- **CNC** — Coefficient of Network Complexity — число дуг на одну работу, плотность сети.
- **J30, J120** — наборы PSPLIB с проектами из 30 и 120 работ.
- **LA** — индикатор доли «коротких» дуг сверх минимума (дуги между соседними уровнями сети); в PSPLIB почти 0.
- **OS** — Order Strength — доля пар работ, связанных путём в графе; чем больше, тем «последовательнее» проект.
- **PSPLIB** — Project Scheduling Problem Library — стандартная библиотека тестовых проектов RCPSP (Kolisch, Sprecher).
- **RCPSP** — Resource-Constrained Project Scheduling Problem — задача календарного планирования проекта с ограниченными ресурсами.
- **RF** — Resource Factor — средняя доля ресурсов, нужных одной работе.
- **RS** — Resource Strength — сила ресурса по Kolisch: 0 — ресурса хватает только на самую «жадную» работу, 1 — на всё раннее расписание сразу.
- **TF** — Topological Float — индикатор того, насколько работы могут сдвигаться между уровнями сети.
