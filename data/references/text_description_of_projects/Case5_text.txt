Дана задача с двумя проектами по 92 работы с ограниченными ресурсами (RCMPSP / MPSPLIB). 
Постановка задачи: необходимо разработать расписание для всех работ, принадлежащих нескольким проектам, таким образом, чтобы:
- соблюдались все отношения предшествования внутри каждого проекта.
- суммарное использование каждого ресурса в любой момент времени не превышало его доступной мощности.
Цель — минимизировать общую продолжительность выполнения всех проектов.
Нижняя граница makespan (CPL каждого проекта без учёта ресурсов): 88 единиц времени.
Эвристика на вход должна принимать следующие аргументы:
- `jobs: list[dict]` — список проектов. Каждый элемент содержит:
    - `project_id` (`int`) — уникальный идентификатор проекта;
    - `num_activities` (`int`) — количество работ (активностей) в проекте;
    - `due_date` (`int`) — директивный срок завершения проекта (может быть 0 (не задан), в этом случае игнорировать);
    - `activities` (`list[dict]`) — список активностей проекта:
        - `id` (`int`) — уникальный идентификатор активности;
        - `duration` (`int`) — длительность выполнения;
        - `resources_required` (`list[int]`) — потребление ресурсов, заданное в виде массива по индексам ресурсов (например: `[r1, r2, r3, ...]`);
        - `successors` (`list[int]`) — список ID последующих активностей (предшествование внутри проекта).
- `resources: list[dict]` — список ресурсов. Каждый элемент содержит:
    - `id` (`int`) — уникальный идентификатор ресурса;
    - `type (str)` — `"global"`;
    - `capacity` (`int`) — мощность ресурса.
Требования к решению:
- Реализуй подходящий эвристический алгоритм, который решит эту задачу.
- Верни полный Python-код функции solve_scheduling(jobs, resources).
- Если в данных не хватает критически важного контекста, не придумывай новые входные поля и не меняй контракт функции; используй только описанные поля и делай минимальные, явно отраженные в коде допущения.
- При выборе решения опирайся на эвристический подход, который:
    - учитывает ограничения предшествования внутри проектов;
    - учитывает ограничения по ресурсам;
    - направлен на минимизацию общей длительности выполнения всех проектов.
