Дана стандартная задача календарного планирования с ограничениями на ресурсы (RCPSP - Resource-Constrained Project Scheduling Problem).
В задаче 30 работ, которые должны быть выполнены с учетом двух типов ограничений:
1. Ограничения предшествования: каждая работа может начаться только после завершения всех её работ-предшественников.
2. Ограничения возобновляемых ресурсов: в любой момент времени суммарное потребление каждого из 4 типов ресурсов не должно превышать их доступную мощность.
Цель — минимизация общего времени выполнения проекта (makespan)
Длина критического пути (нижняя граница makespan): 38 единиц времени.
Эвристика должна принимать такие аргументы:
- `jobs: list[dict]` — список работ. Каждый элемент содержит:
    - `id` (`int`) — уникальный идентификатор работы
    - `duration` (`int`) — длительность выполнения работы
    - `predecessors` (`list[int]`) — список идентификаторов работ-предшественников, которые должны быть завершены до начала данной работы
    - `successors` (`list[int]`) — список идентификаторов работ-преемников
    - `resource_requirements` (`list[dict]`) — потребление возобновляемых ресурсов в формате:
        `[{"resource_id": int, "amount": int}, ...]`
        Пустой список `[]` означает, что работа не требует ресурсов.
- `resources: list[dict]` — список возобновляемых ресурсов. Каждый элемент содержит:
    - `id` (`int`) — уникальный идентификатор ресурса (`0..3` для `J30`)
    - `name` (`str`) — название ресурса
    - `capacity` (`int`) — доступная мощность ресурса в каждый момент времени
    - `type` (`str`) — тип ресурса; значение: `"renewable"`
Требования к решению:
- Реализуй подходящий эвристический алгоритм, который решит эту задачу.
- Верни полный Python-код функции solve_scheduling(jobs, resources).
- Если в данных не хватает критически важного контекста, не придумывай новые входные поля и не меняй контракт функции; используй только описанные поля и делай минимальные, явно отраженные в коде допущения.
