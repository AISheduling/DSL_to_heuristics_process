Дана стандартная задача планирования на одной машине с общим директивным сроком (Restricted Single-Machine Common Due Date Problem).
Условия задачи:
- Есть 50 работ.
- Каждая работа имеет детерминированное время выполнения `p(i)`.
- Все работы должны быть выполнены на одном ресурсе (машине).
- Для всех работ установлен единый общий срок `d`.
- Для каждой работы заданы индивидуальные штрафы:
- `a(i)` — штраф за опережение, если работа завершена до срока `d`.
- `b(i)` — штраф за опоздание, если работа завершена после срока `d`.
Общий директивный срок `d` вычисляется по формуле:
`d = floor(SUM_P * h)`, где `SUM_P` — суммарная длительность всех работ, `h` — коэффициент ограничительности.
Для данного инстанса:
- `SUM_P = 533`
- `h = 0.6`
- `d = 106`
Значение `d` не хранится в полях отдельных работ — его нужно вычислить из данных или использовать значение `106`.
Цель — найти такую последовательность выполнения работ, которая минимизирует общую сумму штрафов за опережение и опоздание для всех работ.
Эвристика на вход должна принимать такие аргументы:
- `jobs: list[dict]` — список работ. Каждый элемент содержит:
    - `id (int)` — уникальный идентификатор работы
    - `duration (int)` — длительность выполнения
    - `resources_required (dict[str, int])` — всегда `{"1": 1}`, каждая работа занимает машину целиком
    - `penalties (dict)` — штрафы за отклонение от срока:
        - `earliness_unit_penalty (int)` — штраф за раннее выполнение (за единицу времени)
        - `tardiness_unit_penalty (int)` — штраф за опоздание (за единицу времени)
- `resources: list[dict]` — список ресурсов. Каждый элемент содержит:
    - `id (int)` — уникальный идентификатор ресурса
    - `capacity (int)` — доступная мощность ресурса
    - `type` (`str`) — тип ресурса; значение: `"renewable"`
Требования к решению:
- Реализуй подходящий эвристический алгоритм, который решает эту задачу.
- Верни полный Python-код функции solve_scheduling(jobs, resources).
- Если в данных не хватает критически важного контекста, не придумывай новые входные поля и не меняй контракт функции; используй только описанные поля и делай минимальные, явно отраженные в коде допущения.
- Выбери разумную эвристику для минимизации суммарных штрафов за earliness/tardiness.
