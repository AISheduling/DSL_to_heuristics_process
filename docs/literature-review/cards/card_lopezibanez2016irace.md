| 3. Что генерируется | Ничего не генерируется в виде кода: выбирается конфигурация — значения числовых, порядковых и категориальных параметров (в т. ч. условных) заданного алгоритма. Через категориальные параметры и грамматики это превращается в выбор компонентов и сборку алгоритма из готовых частей (§5.4) | §2.1, §3.2, §5.4; прил. A2 |
| 4. Интерфейс с ядром | Алгоритм — чёрный ящик: irace вызывает targetRunner с конфигурацией θ и инстансом i и получает стоимость c(θ, i); для многокритериальных задач — отдельный targetEvaluator. Пространство параметров задаётся файлом с типами, диапазонами, условиями и запретами | рис. 2; §3.5, §4.1, §4.2; прил. A |
| 5. Контекст, который видит модель | н/п (LLM нет); «вход» поиска — описание пространства параметров и значения стоимости по инстансам | §3.2; прил. A2 |
| 6. Кто выбирает контекст | н/п. Пространство параметров задаёт пользователь | прил. A2 |
| 7. Механизм поиска | Итеративные гонки: выборка конфигураций из распределений (усечённое нормальное для числовых, дискретное для категориальных) → гонка: конфигурации прогоняются инстанс за инстансом, статистически худшие отбрасываются (тест Фридмана или парный t-тест, α = 0,05) → обновление распределений в сторону элиты. Дополнительно: мягкий рестарт при преждевременной сходимости, элитистская версия (лучшие конфигурации не теряются между гонками) | §3.1–3.4, алг. 1, рис. 1 |
| 8. Модели | н/п | — |
| 9. Baselines | Конфигурация по умолчанию (ACOTSP, MOACO); сравнение элитистского и неэлитистского irace. С другими конфигураторами (SMAC, ParamILS и др.) экспериментально не сравнивается — только обзор в §2.3 | §4.1–4.3, рис. 5, 7, 9 |
| 10. Данные | ACOTSP: 200 обучающих и 200 тестовых евклидовых TSP по 2 000 узлов. MOACO: по 10 обучающих и 60 тестовых инстансов на каждый из 6 размеров (500–1 000). SPEAR: 302 обучающих и 302 тестовых SAT-инстанса. Тест всегда отделён от обучения. Отдельно измеряется однородность обучающего набора (коэффициент конкордации Кендалла W: 0,98 / 0,99 / 0,16) | §4.1, §4.3 |
| 11. Корректность | н/п в смысле генерации кода. Невозможные комбинации параметров исключаются заранее (forbidden configurations); корректность решения — ответственность целевого алгоритма | §3.5 |
| 12. Стоимость | Бюджет задаётся явно как число запусков целевого алгоритма (maxExperiments: 5 000 для ACOTSP и MOACO, 10 000 для SPEAR) плюс лимит времени на запуск (20 с, 4·(n/100)² с, 300 с). Бюджет распределяется по итерациям гонки; гонка экономит запуски, рано отбрасывая плохие конфигурации. Это готовая единица для оси 12 — «число запусков решателя» | §3.2, §4.1, §4.3; рис. 4 |
| 13. Статистика | 30 независимых прогонов irace на сценарий; тест каждой найденной конфигурации на отдельном наборе; сравнение вариантов — тест Уилкоксона или t-тест (p = 0,90; 0,97; 0,97 — различий нет). Внутри гонок статистические тесты используются как эвристика отбора, а не для строгих выводов | §3.2, §4.1, §4.3, рис. 9 |

| 15. Результат и ограничения | irace находит конфигурации заметно лучше заданных по умолчанию (ACOTSP, MOACO); элитистская версия не хуже обычной и устойчивее на неоднородных наборах инстансов (SPEAR). Ограничения (в т. ч. авторские): не рассчитан на сценарии, где главное — время работы; плохо подходит, когда один запуск очень дорогой; модель выборки не учитывает взаимодействия параметров; настройки по умолчанию нужно подстраивать под однородность инстансов | §4, §6 |
