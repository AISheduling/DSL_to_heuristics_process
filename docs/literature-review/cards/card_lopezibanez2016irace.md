| 15. Результат и ограничения | irace находит конфигурации заметно лучше заданных по умолчанию (ACOTSP, MOACO); статистически значимых различий между элитистской и обычной версией нет ни в одном из трёх сценариев; на неоднородном SPEAR обычная версия теряла хорошую элитную конфигурацию в 8 из 30 прогонов и дала две худшие конфигурации — бо́льшая устойчивость элитистской версии авторами заявлена как гипотеза. Ограничения (в т. ч. авторские): не рассчитан на сценарии, где главное — время работы; плохо подходит, когда один запуск очень дорогой; модель выборки не учитывает взаимодействия параметров; настройки по умолчанию нужно подстраивать под однородность инстансов; при слишком малом бюджете результат может быть не лучше случайных конфигураций | §4, §6, §4.3, §4.4, рис. 8–10 |
| Чем отличаемся от этой работы | irace офлайн подбирает значения параметров (и выбор готовых компонентов) заданного алгоритма итеративными гонками при бюджете в запусках решателя, ничего не генерируя, а мы через LLM однократно генерируем под инстанс новый код двух функций SSGS.<br>**Сходство:**<br>— ядро алгоритма фиксировано, меняется только заполняемая часть: у них значения параметров и выбор компонентов, у нас код функций.<br>**Отличия:**<br>— *режим:* у них офлайн-настройка под класс инстансов, у нас генерация под инстанс;<br>— *что меняется:* параметры против кода; через категориальные параметры и грамматики irace собирает алгоритм из готовых частей (§5.4) — классическая альтернатива генерации кода;<br>— *бюджет:* число запусков целевого алгоритма (5 000–10 000), у нас выходные токены;<br>— *оценка:* отдельный тест, 30 прогонов, учёт однородности набора (Kendall W), у нас 5 инстансов без чекера (issue #1).<br>**Вывод:** baseline пласта C для столбца «параметры» карты 1: настройка параметров фиксированного правила или SGS при равном числе запусков решателя. Для направления научрука (2) возможен baseline сборки из готовых вариантов `select_job_fn` / `allocate_fn` как категориальных параметров — это наша идея, в статье для RCPSP не проверено. Методологический образец для оценки: бюджет в запусках, отдельный тест, многократные прогоны, проверка однородности инстансов. | §1, §4, §5.4, §6 |
