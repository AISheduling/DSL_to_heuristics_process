| 15. Результат и ограничения | Знания из GP улучшают LLM, принимающую онлайн-решения, но важна форма подачи: упрощение контекста (Feature Selection) и явная логика (Rule Follow, Rule Reference) работают, выделение важных признаков (Feature Hint) — ненадёжно. Feature Selection — лучший компромисс по токенам, Rule Follow — по качеству. Rule Follow при order strength 0,75 точно воспроизводит GP-правило (σ = 0), т. е. LLM просто исполняет правило; при меньшей order strength — менее стабильна. Описательно, без тестов (табл. 3): Basic LLM хуже исходного GP-правила по среднему на 13 из 15 инстансов; лучшее из LLM-вариантов (выбранное постфактум для каждого инстанса) лучше GP-правила на 6, равно на 5, хуже на 4. Ограничения: 15 инстансов размера 30, тест на тех же проектах; одна модель; нет сравнения с классическими правилами и с самой GP без LLM по значимости; LLM-решения на порядки дороже исполнения правила | §4.2, §5, табл. 3, 4, рис. 5, 7 |
| Чем отличаемся от этой работы | Tian et al. используют LLM как онлайн-решатель, выбирающий пару «работа–режим» в каждой точке DM-RCPSP при варьируемых формах знаний из GP в контексте, а мы однократно генерируем код двух функций SSGS под каждый инстанс статического RCPSP по его описанию и метаданным и варьируем представление задачи (Text / DSL / Skeleton).<br>**Сходство:**<br>— семейство RCPSP, минимизация makespan;<br>— фактор эксперимента — состав и форма контекста LLM (4 формы знаний против Basic); один из двух ближайших аналогов для направления (1): здесь информация об инстансе — в контексте LLM, у Luo 2026 — во входах офлайн-правила;<br>— поиска на стороне LLM нет, как и у нас;<br>— считают токены; допустимость обеспечивает среда, независимого чекера нет ни там, ни у нас.<br>**Отличия:**<br>— *что генерируется:* у них решение в каждой точке, у нас код эвристики;<br>— *режим:* оба онлайн, но на разном уровне: у них вызов LLM на каждое решение внутри расписания, у нас — одна генерация кода на инстанс по его описанию и метаданным (сырых данных LLM не видит);<br>— *гранулярность:* не исследуется; у нас две функции;<br>— *класс задачи:* у них динамический многомодовый, у нас статический одномодовый RCPSP;<br>— *оценка:* у них 15 инстансов J30M3, тест на тех же проектах, «нормализованный makespan» не определён; у нас качество не подтверждено (issue #1);<br>— *стоимость:* у них 60–185 тыс. токенов (вкл. рассуждения) на прогон; у нас выходные токены одной генерации; напрямую не сопоставимо. | — |
