| 4. Интерфейс с ядром | Динамическая среда моделирования формирует множество кандидатов, уже допустимых по предшествованию и ресурсам; LLM выбирает одного; среда запускает работу, раскрывает длительность и продвигает состояние до следующей точки решения | §3.1, рис. 3 |
| 5. Контекст, который видит модель | Системная инструкция (задача, ограничения на выбор, порядок рассуждения, политика объяснений, формат вывода) + состояние проекта + определения признаков + таблица признаков кандидатов + необязательное знание из GP в одной из 4 форм: Feature Selection (в таблице только отобранные признаки), Feature Hint (все признаки, отобранные выделены как важные), Rule Reference (GP-правило как совет), Rule Follow (GP-правило как предписание). | 15. Результат и ограничения | Знания из GP улучшают LLM, принимающую онлайн-решения, но важна форма подачи: упрощение контекста (Feature Selection) и явная логика (Rule Follow, Rule Reference) работают, выделение важных признаков (Feature Hint) — ненадёжно. Feature Selection — лучший компромисс по токенам, Rule Follow — по качеству. Rule Follow при order strength 0,75 точно воспроизводит GP-правило (σ = 0), т. е. LLM просто исполняет правило; при меньшей order strength — менее стабильна. Ограничения: 15 инстансов размера 30, тест на тех же проектах; одна модель; нет сравнения с классическими правилами и с самой GP без LLM по значимости; LLM-решения на порядки дороже исполнения правила | §4.2, §5, табл. 3, 4, рис. 5, 7 |
