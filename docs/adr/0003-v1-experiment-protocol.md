# ADR 0003. Протокол первого эксперимента В1: выборка, эталоны, метрика

- Дата: 2026-10-26
- Статус: черновик (п. 1–4 приняты на шаге 2; п. 5 фиксируется до запуска генерации)
- Связано: ADR 0001 (ядро, чекер), ADR 0002 (индикаторы), `candidate_questions.md` — В1, В2

## Контекст

Вопрос В1: дает ли генерация кода эвристики под конкретный проект по его метаданным
выигрыш по ARPD относительно генерации без метаданных и офлайн-правил при одном
построении SSGS на инстанс. Первый эксперимент — уровни (а) «LLM под инстанс с
12 индикаторами» и (б) «LLM под инстанс без метаданных» на PSPLIB J60/J120. Чтобы
результат нельзя было подогнать, выборка, эталоны и правила подсчета фиксируются до
генерации.

## Решение

1. **Выборка** (`experiments/v1_pilot/make_sample.py` → `sample.json`, в git).
   По одному инстансу на каждую комбинацию параметров генератора ProGen: J60 — 48,
   J120 — 60, всего 108; номер инстанса (1..10) выбирается случайно при `seed = 2026`.
   Так в выборку попадают все сочетания NC, RF, RS генератора, а не похожие проекты.
   **Пилот** — 15 случайных инстансов выборки из каждого набора (30), тот же seed.
   J30 в тест не входит: это набор для отладки.
2. **Эталоны** (`src/references.py`).
   - BKS (лучшее известное решение) — минимум верхних границ из файлов решений PSPLIB
     (`opt` для J30, `hrs`) и RCPLIB v6 (`UB-lit`); источник пишется в `bks_source`.
     У 17 инстансов J120 `UB-lit` в RCPLIB хуже, чем `hrs` PSPLIB, — берется лучшее.
   - Нижняя граница — максимум из CPM, `lb` PSPLIB и `LB-lit` RCPLIB.
   - CPM считается по инстансу и сверяется с RCPLIB и с MPM-Time в файле `.sm`
     (совпадает на всех 1560 инстансах).
   - Доказанный оптимум (`optimal`, LB = BKS): J30 — 480/480, J60 — 464/480,
     J120 — 328/600; в выборке — 46/48 и 33/60.
3. **Метрика** (`src/metrics.py`). RPD = 100 · (makespan − BKS) / BKS для одного
   прогона; ARPD — среднее RPD. Основной эталон — BKS (как в `candidate_questions.md`);
   дополнительно отклонение от CPM, принятое в литературе для J120.
4. **Прогоны без допустимого расписания** (статус чекера не `valid`, таймаут, ошибка
   компиляции и т. д.) в ARPD не входят; рядом всегда приводится доля допустимых
   прогонов (`summarize_rpd`). Сравнение уровней по ARPD без доли допустимых не
   приводится.
5. **Фиксируется до запуска генерации** (шаги 3–4): модель и температура, число
   генераций на инстанс (план — 5), текст промпта для (а) и (б), состав DSL,
   минимальный интересный эффект δ (ориентир 0,5 п. п.), статистический тест
   (парный Уилкоксон по инстансам: среднее RPD по генерациям инстанса).

## Последствия

- Любая перегенерация выборки меняет `sample.json` и видна в diff; тест сверяет
  закоммиченную выборку с правилом.
- Эталоны зависят от скачанных PSPLIB и RCPLIB (`SOURCES.md` с SHA-256); без RCPLIB
  BKS не меняются, но нижние границы слабее (меньше доказанных оптимумов).
