# ADR 0003. Протокол первого эксперимента В1: выборка, эталоны, метрика

- Дата: 2026-10-26
- Статус: черновик (п. 1–4 приняты на шаге 2, п. 5–6 — на шаге 3, п. 7 — на шаге 4; п. 8 фиксируется до полного запуска)
- Связано: ADR 0001 (ядро, чекер), ADR 0002 (индикаторы), `candidate_questions.md` — В1, В2

## Контекст

Вопрос В1: дает ли генерация кода эвристики под конкретный проект по его метаданным
выигрыш по ARPD относительно генерации без метаданных и офлайн-правил при одном
построении SSGS на инстанс. Первый эксперимент — уровни (а) «LLM под инстанс с
12 индикаторами» и (б) «LLM под инстанс без метаданных» на PSPLIB J60/J120. Чтобы
результат нельзя было подогнать, выборка, эталоны и правила подсчета фиксируются до
генерации.

## Решение

1. **Выборка** (`experiments/v1_pilot/make_sample.py` → `sample.json`, в git).
   По одному инстансу на каждую комбинацию параметров генератора ProGen: J60 — 48,
   J120 — 60, всего 108; номер инстанса (1..10) выбирается случайно при `seed = 2026`.
   Так в выборку попадают все сочетания NC, RF, RS генератора, а не похожие проекты.
   **Пилот** — 15 случайных инстансов выборки из каждого набора (30), тот же seed.
   J30 в тест не входит: это набор для отладки.
2. **Эталоны** (`src/references.py`).
   - BKS (лучшее известное решение) — минимум верхних границ из файлов решений PSPLIB
     (`opt` для J30, `hrs`) и RCPLIB v6 (`UB-lit`); источник пишется в `bks_source`.
     У 17 инстансов J120 `UB-lit` в RCPLIB хуже, чем `hrs` PSPLIB, — берется лучшее.
   - Нижняя граница — максимум из CPM, `lb` PSPLIB и `LB-lit` RCPLIB.
   - CPM считается по инстансу и сверяется с RCPLIB и с MPM-Time в файле `.sm`
     (совпадает на всех 1560 инстансах).
   - Доказанный оптимум (`optimal`, LB = BKS): J30 — 480/480, J60 — 464/480,
     J120 — 328/600; в выборке — 46/48 и 33/60.
3. **Метрика** (`src/metrics.py`). RPD = 100 · (makespan − BKS) / BKS для одного
   прогона; ARPD — среднее RPD. Основной эталон — BKS (как в `candidate_questions.md`);
   дополнительно отклонение от CPM, принятое в литературе для J120.
4. **Прогоны без допустимого расписания** (статус чекера не `valid`, таймаут, ошибка
   компиляции и т. д.) в ARPD не входят; рядом всегда приводится доля допустимых
   прогонов (`summarize_rpd`). Сравнение уровней по ARPD без доли допустимых не
   приводится.
5. **DSL из инстанса** (`src/dsl_builder.py`, шаг 3). `build_dsl(instance, composition)`:
   постановка (одномодовый RCPSP, возобновляемые ресурсы, цель — makespan) одинакова для
   всех инстансов; индикаторы — в блоке `project_indicators` с тремя знаками, как в RCPLIB.
   Составы: `none` — без блока (уровень (б)), `all` — 12 индикаторов (уровень (а)),
   `network` (n + 7 сетевых) и `resource` (n + 4 ресурсных) — для В2. Имя инстанса,
   эталоны и срок из файла PSPLIB в DSL не попадают. Каркас читает блок в
   `DSLMeta.indicators`; `build_state` принимает DSL-словарь.
6. **Промпт** (`src/llm_clients/prompt_v1.py`, версия `v1-2026-10-27`). Системный промпт
   и шаблон сообщения одинаковы для (а) и (б), различается только подставленный DSL.
   Промпт описывает только RCPSP: контракт двух функций SSGS, поля `Job`, `snapshot`,
   `meta` и смысл 12 индикаторов; полей весенних постановок (NRR, группы выбора, одна
   машина, многопроектность) и метрик `calculate_metrics.py` в нем нет. Весенний промпт
   Skeleton не меняется — он нужен для воспроизведения.
7. **Генерация** (`experiments/v1_pilot/generate.py`, шаг 4).
   - Модели (2026-10-27): `anthropic/claude-haiku-5-5` и
     `openrouter/qwen/qwen3.8-flash` через прокси LiteLLM, отдельный ключ команды
     «LLM scheduling». Каждая модель — отдельный запуск (`--run`); модель — фиксированный
     фактор: (а) и (б) сравниваются только внутри одной модели. Весной использовалась
     `gpt-5.4-nano`, поэтому осенние числа с весенними напрямую не сравниваются.
   - `temperature` 0.7, как весной. `max_tokens` 16000: у Haiku скрытое рассуждение
     занимает около 4 тыс. токенов и входит в лимит; при 5000 ответ обрезался (проба
     `probe-haiku`). Уровень рассуждения не задается — остается по умолчанию у провайдера.
   - Запрашивается ответ в JSON (`response_format = json_object`), но Anthropic через
     прокси отвечает в markdown-ограждении ```` ```json … ``` ````; скрипт берет первый
     JSON-объект ответа.
   - Один вызов = инстанс × уровень × номер генерации; ответ — отдельный файл
     `generations/<run>/<инстанс>__<уровень>__g<k>.json` (DSL, ответ, токены, время,
     ошибка). Настройки запуска и коммит — в `manifest.json`; продолжить запуск с
     другими настройками нельзя.
   - Сетевые ошибки — до 3 попыток (`api_error`); ответ без JSON или без обеих функций —
     `parse_error`; ответ, обрезанный по лимиту токенов, — `truncated`. Такие генерации
     не перезапрашиваются (кроме явного `--retry-errors` после сбоя прокси) и входят в
     долю недопустимых (п. 4). Токены рассуждения записываются отдельно, если прокси их
     отдает.
   - **Пилот**: 30 инстансов × 2 уровня × 3 генерации = 180 вызовов на модель, запуски
     `pilot-<модель>`. Цель пилота — проверить цепочку и стоимость, а не сделать вывод
     по В1.
8. **Фиксируется до полного запуска** (108 × 2 × 5 = 1080 вызовов): минимальный
   интересный эффект δ (ориентир 0,5 п. п.) и статистический тест (парный Уилкоксон по
   инстансам: среднее RPD по генерациям инстанса). Модель и промпт после пилота
   меняются только с новой версией промпта и новым запуском.

## Последствия

- Любая перегенерация выборки меняет `sample.json` и видна в diff; тест сверяет
  закоммиченную выборку с правилом.
- Эталоны зависят от скачанных PSPLIB и RCPLIB (`SOURCES.md` с SHA-256); без RCPLIB
  BKS не меняются, но нижние границы слабее (меньше доказанных оптимумов).
