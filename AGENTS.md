# AGENTS.md

Правила работы агентов с этим репозиторием. Общие для всех участников, хранятся в git.
Личные правила — в `CLAUDE.local.md` (не в git).

## О проекте

Генерация эвристик RCPSP через LLM по описанию проекта (DSL) и их прогон в каркасе SSGS.
Текущий этап — эксперимент В1: дает ли код эвристики, сгенерированный по 12 индикаторам
проекта, выигрыш по ARPD относительно генерации без метаданных и офлайн-правил
(PSPLIB J60/J120). Протокол — `docs/adr/0003-v1-experiment-protocol.md`.

Структура и назначение модулей — в `README.md`, раздел «Структура проекта». Решения —
в `docs/adr/`: прочитай нужный ADR до изменения ядра, чекера, индикаторов или протокола В1.

## Команды

- Зависимости: `pip install -r requirements-dev.txt` (Python 3.12).
- Все тесты: `python -m pytest` (~45 с). Один файл: `python -m pytest tests/test_metrics.py`.
- Сверки с PSPLIB и RCPLIB пропускаются, если данные не скачаны: `data/psplib/SOURCES.md`,
  `data/rcplib/SOURCES.md`.
- Цепочка В1: `experiments/v1_pilot/generate.py` → `run_kernel.py` → `evaluate.py`,
  у каждого `--run <имя>`. Проверка без вызовов API: `generate.py --dry-run`.
- Генерация требует `LITELLM_API_KEY` в окружении и стоит денег — запускай только по просьбе.

## Инварианты (не нарушать)

- `src/schedule_checker.py` не импортирует каркас (`scheduler_skeleton.py`) — это
  независимая проверка. Makespan в отчетах берется из чекера, а не из каркаса.
- Статусы прогона — только из `runner_common.STATUSES` (ADR 0001). Недопустимые прогоны
  не входят в ARPD; рядом с ARPD всегда доля допустимых.
- Протокол В1 фиксируется до генерации: не меняй `experiments/v1_pilot/sample.json`, seed
  (2026), эталоны (`src/references.py`) и правила подсчета ради результата. Если изменение
  протокола нужно — сначала запись в ADR 0003.
- Промпт В1 (`src/llm_clients/prompt_v1.py`) одинаков для уровней (а) и (б); меняется
  только DSL. После правки промпта поднимай `PROMPT_VERSION`.
- В DSL не попадают имя инстанса, эталоны и срок из файла PSPLIB.
- Модели сравниваются только внутри одного запуска (модель — фиксированный фактор).
- Каждый запрос к прокси — с `PROXY_CACHE` (no-cache, no-store), иначе прокси отдает
  сохраненные ответы. После запуска смотри `fast_replies` и `repeated_replies`.
- Стоимость запуска — фактическое списание Spend в LiteLLM (`evaluate.py --spent-usd`),
  а не оценка по токенам.
- Весенние раннеры и промпты (`experiments/runners/`, `llm_client_for_*`) не меняются:
  они нужны для воспроизведения.

## Что не попадает в git

- `data/psplib/*`, `data/rcplib/*` кроме `SOURCES.md` — лицензия источников.
- `experiments/v1_pilot/generations/` — сырые ответы LLM. В git идут `results/<run>/`.
- `.env`, ключи API, `CLAUDE.local.md`.

Эти правила проверяет хук `tools/hooks/pre-commit` (подключение — ниже).

## Стиль

- Код: комментарии и докстринги по-русски, имена — по-английски. Комментарии короткие,
  объясняют «почему», как в окружающем коде.
- Тест на каждое изменение поведения; негативные тесты для дефектов (см. `tests/test_kernel.py`).
- Документация и ADR — по-русски. Числа в ADR — с источником (запуск, файл, таблица статьи).
- Коммиты — Conventional Commits по-английски: `feat(eval): ...`, `fix(llm): ...`,
  `docs(adr): ...`. Одно логическое изменение на коммит.
- Новый модуль или тест — добавь строку в «Структуру проекта» в `README.md`.

## Хуки

Жесткие проверки, которые нельзя пропустить, в отличие от правил выше:

- `tools/hooks/pre-commit` — блокирует коммит с ключами API и файлами, которым не место
  в git. Подключить один раз: `git config core.hooksPath tools/hooks`.
