# Запуск эксперимента В1

Протокол — `docs/adr/0003-v1-experiment-protocol.md`, пп. 7–10. Скилл описывает порядок
действий и проверки; числа и решения — только в ADR.

## 0. Перед генерацией (обязательно)

1. Согласуй с пользователем: имя запуска (`pilot-<модель>`, `full-<модель>`), модель,
   уровни, число генераций. Полный запуск — 108 × 2 × 5 = 1080 вызовов; пилот —
   `--pilot-only --gens 3`, 180 вызовов.
2. Посчитай оценку стоимости по ценам модели и назови ее. Без явного «да» генерацию не
   запускай.
3. Попроси пользователя записать Spend ключа в LiteLLM **до** запуска.
4. Проверь план и промпт без вызовов API:
   `python experiments/v1_pilot/generate.py --run <run> --model <model> [--pilot-only] --gens <k> --dry-run`
5. Пробный вызов на 1–2 запроса: `--limit 2`. Проверь, что ответ не `truncated` и не
   `parse_error`.

## 1. Генерация

`python experiments/v1_pilot/generate.py --run <run> --model <model> [--pilot-only] --gens <k>`

Запускай в фоне: полный запуск идет долго. Скрипт продолжает прерванный запуск с теми же
настройками; с другими — отказывается, так и задумано (новое имя запуска).

После запуска:
- `ВНИМАНИЕ ... кэш прокси` или ненулевые `fast_replies` / `repeated_replies` — остановись
  и разберись (ADR 0003, п. 7, «Кэш прокси»). Такой запуск в отчет не идет.
- `api_error` после сбоя прокси — `--retry-errors`, только с согласия пользователя.
- Уровень из другого запуска — `--reuse a=<run>`, только если тот запуск без кэша.

## 2. Прогон в каркасе

`python experiments/v1_pilot/run_kernel.py --run <run>`

Результат — `experiments/v1_pilot/results/<run>/runs.csv`, `baselines.csv`, `summary.json`.
Проверь долю `ok` по уровням; всплеск `compile_error` или `runtime_error` — сначала
посмотри несколько генераций глазами (ошибка стенда или модели?).

## 3. Отчет

Попроси Spend **после** запуска; разность — фактическая стоимость.

`python experiments/v1_pilot/evaluate.py --run <run> --spent-usd <разность> --price-in <$> --price-out <$>`

Результат — `report.json`, `report.md`.

## 4. Проверка и запись

1. Сверь в `report.md`: доля допустимых рядом с каждым ARPD; сравнения (а)–(б), (а)–LST,
   (б)–LST с поправкой Холма; стоимость.
2. Новые факты о запуске (стоимость, инциденты, отклонения от протокола) — в ADR 0003.
3. В git идут `results/<run>/` и правка ADR; `generations/` — нет. Коммит — только по
   просьбе пользователя.
4. Итог пользователю: модель, число вызовов, доля допустимых и ARPD по уровням, значимые
   сравнения, стоимость, что не проверено.
